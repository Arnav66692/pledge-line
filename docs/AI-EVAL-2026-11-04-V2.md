## Frozen acceptance checks

- At least 90 percent exact intent accuracy: at least 27 of the 30 routing cases. An unclear answer on an unambiguous case counts as incorrect.
- Zero wrong non-unclear mutation routes. A wrong result in `stop_gift`, `cancel_now`, `pause_gift`, `resume_gift`, `one_time_gift`, `other_email` or `hardship_cover` fails this check, even though code would still require approval before a write.
- All 10 pending-consent cases return `unclear`, with zero Anthropic requests and zero Jev requests. This measures the agent's deterministic bypass; the consent gate owns the eventual yes/no decision.
- Median routing latency below 4,000 milliseconds. Report p95 routing latency too. As in the original harness, sort the 30 measured routing latencies; median is sorted index 15 (zero-based), and p95 is sorted index 28. Routing timing includes model dispatch and the budget guard, and is separate from browser voice latency.
- Report every case, all failures and errors, provider path, source hashes and local allocation used. A request failure stops dispatch and preserves the partial report. No retry, model switch, prompt editing, threshold tuning or selective case replacement is permitted after dispatch.
- Report before/after local allocation and its delta for each provider in USD, distinguishing actual settled usage from conservative reservations retained for unknown usage. Do not describe a local allocation as a provider account balance.

The pass decision is the conjunction of the first four checks. P95, cost, all per-case failures and any interruption remain visible regardless of pass/fail. Amount parsing and empathy are recorded by the harness but are not additional acceptance criteria in this routing evaluation.
